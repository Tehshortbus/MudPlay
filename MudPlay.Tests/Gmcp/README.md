# GMCP replay fixtures

The milestone-1 synthetic sequences come from Anomaly contract 1.0.0 (schema commit `0e9ac9f`, including nullable monster level). Milestone 2 embeds the tagged `contract-v1.1.0` schemas and examples, plus synthetic and captured `13-milestone2` recordings (server `b8fdb38`). They exercise the client and are not evidence of server correctness. Contract 1.2.0 (proposed) adds the `Anomaly.Quests.Names` schema, its valid and invalid examples, and the synthetic `15-quest-names` recording; no capture exists yet. Captured recordings will replace matching replay inputs when the isolated test host supplies them. Preserve capture headers and raw bytes when importing captures.

`Captured/` contains server captures for client replay. Client-to-server text is omitted so login credentials do not enter the public repository; server frames, GMCP raw bytes, headers and build identifiers are preserved. The full evidence remains in the shared contract repository. These replays validate client handling; they do not replace active client/server runs.

The opt-in live xUnit scenarios require disposable accounts in `MUDPLAY_GMCP_ACCOUNT`, `MUDPLAY_GMCP_PASSWORD`, `MUDPLAY_GMCP_SYSOP_ACCOUNT` and `MUDPLAY_GMCP_SYSOP_PASSWORD`. They are skipped during normal regression runs. Coordinate an exclusive test window before running them: one scenario toggles GMCP on the isolated host. `run-live.py` runs them through a passive recorder and accepts the disposable account pairs as JSON on stdin. Its evidence directory must be outside this repository because full captures include login traffic. Never commit those full captures.

The milestone-2 scenarios additionally require `MUDPLAY_GMCP_PRIEST_ACCOUNT` and `MUDPLAY_GMCP_PRIEST_PASSWORD`; `run-live.py` accepts the corresponding `Gpriest` pair. Use `--filter FullyQualifiedName~IsolatedHost_Milestone2Shadow` before `--filter FullyQualifiedName~IsolatedHost_Milestone2Active` and name the tested build with `--server-commit`. The active scenario uses only disposable test characters: coins, party formation, repeated chat, a granted bless, and a walk from Town Gates to Skali's shop and back. It does not restart the host. Full captures contain login traffic and remain private; never commit them.

Run ordinary tests with a fresh scratch `MUDPLAY_DATA_ROOT`, as required by the repository's test guard. Live scenarios are opt-in, never part of an unattended normal regression run.

`14-milestone2-client-active` is the sanitized successful MudPlay active-client connection against server `b8fdb38`; it adds actual party formation, spell/effect changes, live item queries, directed-say text fallback, and shop stock to the replay gate. All client text and server authentication text are omitted; retained server frame bytes are unchanged.
